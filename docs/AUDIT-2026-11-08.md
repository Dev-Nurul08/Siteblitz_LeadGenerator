## 2. Why the leads were not reliable (still to fix — phase 2–3)

The system **assumes** instead of **checking**:
- **No website field = "needs a website", CRITICAL.** OpenStreetMap is incomplete; most businesses
  there have no website tag even when they have a site. Nothing verifies it
  (`detector.py:74-78`). Every such business scores 88 → HOT. → Mostly false HOT leads.
- **Category = need.** Every restaurant, clinic, gym or salon with a working site gets a
  "Mobile App" opportunity (score 83.5, CRITICAL) and "Online Booking" (`detector.py:161-212`).
- **Junk businesses.** "All categories" pulls ATMs, banks, fuel stations, schools, hospitals and
  places of worship (`osm.py:30-41`); chains/brands are never excluded.
- **Wrong merges.** Two different shops with the same name in the same country are merged into one
  (`discovery_service.py:323-335`).
- **False website signals.** A Cloudflare 403 is "broken", a slow site is "no website", any page
  containing the word "appointment" "has online booking", any URL containing `x.com`
  (fedex.com, box.com) is "social media" (`resolver.py:117`, `auditor.py:76-95`, `normalizer.py:243`).
- **Fake certainty.** Confidence is a hard-coded 0.92 (`scorer.py:120`).

## 3. Things that pretend (to remove or make honest — phase 5)
- Enrichment **invents** `info@<domain>` contacts (`enrichment/discovery.py:95-104`).
- Pitch templates contain **untrue claims**: "impressed by your reviews", "we built a preview
  concept", "I browsed your site on my phone" (`ai_personalizer.py:64-160`); fake sender
  "Marcus Vance" and a fake New York address (`sender.py:34-43`).
- "Dispatch" **never sends anything** — it only marks messages SENT (`sender.py:79-107`).
- Hunter.io integration always returns nothing (bad dataclass fields, error swallowed,
  `enrichment/discovery.py:203`).
- The businesses that most need a website have no email, so the email-only pipeline can never
  qualify them.

## 4. Google Maps, Instagram, Facebook, LinkedIn, TikTok — what is possible
- **Google Maps:** scraping the Maps website breaks Google's terms and breaks often. The official
  Places API works, but its terms allow storing only the place ID permanently — not names, phones
  or websites. So Places is used as an optional **live verification** step (with your API key), not
  as the database. OpenStreetMap stays the stored source; CSV import for lists you have rights to.
- **Instagram / Facebook / LinkedIn / TikTok:** no automated logged-in scraping (LinkedIn's terms
  forbid it; it also gets accounts banned). Social profiles are found from the business's own
  listing and website links, then confirmed. A social profile alone never means "needs a website".
- **WhatsApp:** business-initiated WhatsApp messages need the recipient's opt-in; a published
  number is not permission. Phone calls and manual follow-up come first.
